# v0.2 core decomposition

**Status:** A11 design & implementation freeze
**Applies to:** `crates/openmesh-core` on `feat/v0.2.0-unified-workbench`
**Preserves:** All frozen A9 UI contracts, single-source navigation registry, route compatibility, and runtime/settings separation.

---

## 1. Problem Statement

At `v0.1.40`, `crates/openmesh-core` grew into a flat collection of 33 root source files alongside 22 subdirectories. Most prominently:

* `src/domain.rs` grew to **4,248 lines**, conflating seven distinct domain bounded contexts:
  1. WorkEvent protocol and evidence models
  2. WorkSignal wire protocol
  3. Current State and Catch-Up projections
  4. WorkEvent correction chains and effective presentations
  5. Work Proxy Profile and authority ladder rules
  6. Proxy Context Pack sanitization and validation
  7. Proxy Question, Draft, and Ask runtime contracts
* Internal test runners experienced intermittent concurrency races in `tests/context_pack_boundary.rs` due to shared nanosecond temp directory collisions during parallel multi-threaded test runs.

---

## 2. Target Core Architecture & Boundaries

The decomposed domain contracts maintain a strict, unidirectional dependency hierarchy:

```text
┌────────────────────────────────────────────────────────┐
│                   domain::proxy_draft                  │
│       (ProxyQuestion, ProxyDraft, Runtime Wire)        │
└───────────────────────────┬────────────────────────────┘
                            │ depends on
┌───────────────────────────▼────────────────────────────┐
│                  domain::context_pack                  │
│      (ProxyContextPack, Sanitization, Invariants)      │
└─────────────┬────────────────────────────┬─────────────┘
              │ depends on                 │ depends on
┌─────────────▼──────────────┐ ┌───────────▼─────────────┐
│    domain::projections     │ │     domain::profile     │
│ (CurrentState, CatchUpView)│ │  (WorkProxyProfile,     │
└─────────────┬──────────────┘ │   Authority Ladder)     │
              │ depends on     └─────────────────────────┘
┌─────────────▼──────────────┐
│     domain::corrections    │
│  (WorkEventCorrection,     │
│   Effective Presentation)  │
└─────────────┬──────────────┘
              │ depends on
┌─────────────▼──────────────┐ ┌─────────────────────────┐
│       domain::events       │ │     domain::signals     │
│ (WorkEvent, EvidenceRef,   │ │ (WorkSignal, Payload,   │
│  Semantics Validation)     │ │  Kind, ProducerRef)     │
└────────────────────────────┘ └─────────────────────────┘
```

### Module Responsibilities

1. **`domain::events`**: Fundamental wire types (`WorkEvent`, `EvidenceAttachment`, `EvidenceRef`, `GitState`, `HeliSnapshot`) and semantic validators (`validate_event_semantics`). Independent of higher-level projections.
2. **`domain::signals`**: Ephemeral observer signals (`WorkSignal`, `WorkSignalPayload`, `WorkSignalKind`, `ProducerRef`, `ActorRef`) and signal validation.
3. **`domain::corrections`**: Event correction model (`WorkEventCorrection`, `CorrectionKind`, `EffectiveEventPresentation`, `effective_presentation`, `effective_kind_for`, `effective_summary_for`).
4. **`domain::projections`**: Read models derived from events and signals (`CurrentStateProjection`, `PendingAttentionItem`, `CatchUpView`, `CatchUpWindow`).
5. **`domain::profile`**: Declarative authority and work proxy preferences (`WorkProxyProfile`, `AuthorityRule`, `ProxyAuthorityLevel`, `PrivacyRule`, `DefaultRefusalRule`).
6. **`domain::context_pack`**: Deterministic, sanitized projection packaging for LLM/prompt boundary (`ProxyContextPack`, `ContextPackAuthoritySummary`, `ContextPackPrivacySummary`, `validate_proxy_context_pack`).
7. **`domain::proxy_draft`**: Request/response contracts for proxy drafting (`ProxyQuestion`, `ProxyPromptBundle`, `ProxyRuntimeRequest`, `ProxyRuntimeOutput`, `ProxyDraft`, `ProxyDraftTraceMetadata`).

### Compatibility Invariant

`openmesh_core::domain` maintains a full re-export surface in `domain/mod.rs`. External crates (`openmesh-cli`, `src-tauri`) and test suites continue to reference `openmesh_core::domain::*` without breaking changes.

## 3. Concurrency Hardening (`context_pack_boundary.rs`)

The parallel test flake observed under full workspace execution was traced to directory naming in `temp_project`:
Multiple concurrent test threads (such as `can_draft_does_not_generate_draft` and `must_ask_human_does_not_simulate_human_confirmation`) running on the same process share identical label prefixes and sub-microsecond timestamps. When one test's directory initialization interleave-cleans or overwrites another's `project.json`, `load_project()` observes a `WorkspaceMismatch`.

**Resolution:**
Integrated an atomic sequential counter (`AtomicU64`) into directory generation in `temp_project` and added a dedicated regression test (`concurrent_authority_pack_builds_do_not_collide`) verifying 8 concurrent worker threads generating distinct authority packs without collision.
