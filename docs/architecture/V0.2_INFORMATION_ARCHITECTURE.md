# v0.2 information architecture

**Status:** A9 design freeze (source-backed). Navigation implementation follows this document.
**Applies to:** `feat/v0.2.0-unified-workbench` after A8.
**Does not:** redesign visuals, change Agent Engine / Continuity domain / slash-command grammar, or import `wip/oauth-proxy-followup`.

OpenMesh is a local-first Agent Workbench. The visible product must answer, in this order:

1. What project am I working on?
2. What is the agent doing?
3. What work and context already exist?
4. Which agent / provider / runtime am I using?
5. What needs my attention?

A new user must not need Continuity track history, proxy lineage, mesh protocol terms, or internal release phases to use the app.

Related: [PRODUCT_CENTER.md](./PRODUCT_CENTER.md), [ADR-0001](./ADR-0001-agent-workbench-center.md), [LLM_RUNTIME_INVENTORY.md](./LLM_RUNTIME_INVENTORY.md).

### Mandatory principles (frozen)

**Chat is primary.** Selecting a project continues to land on `/agent-chat`. Chat is not nested under Agents.

**Workspace owns project artifacts.** Home, Context, Docs, Notes, Canvas, Sprint. Overview+Build merge so “Build” is not a second product.

**Agents owns session interoperability.** Only Sessions. Chat stays a sibling primary, not a child.

**Runtime is infrastructure.** Provider catalog, OAuth, HTTP proxy listener, usage, Pending & LAN. Network is not a default-expanded product identity. Runtime starts **collapsed**.

**Continuity is supporting state.** Nav label: **Pending & LAN**. Canonical URL stays `/continuity`. In-page groups become Attention / Share / Advanced so users see “what needs attention / what can I hand off?”, not track names.

**Settings is preferences.** Chat provider **keys** stay in Settings → Provider (Agent Engine / `LlmRuntime`). That is *not* the HTTP proxy catalog. Settings must not use the word “Runtime” as a group label.

### Source-backed deviation from the A9 sketch

The program sketch listed Runtime → Providers as if it were Chat setup. Inspection shows two different “providers”:

| User need | Canonical home | Route |
|-----------|----------------|-------|
| Chat / Agent Engine API key, name, default model | Settings → Provider | `/settings?section=provider` |
| HTTP proxy upstream registry (models behind the optional listener) | Runtime → Providers | `/proxy-providers` |

A9.8 missing-provider CTA therefore goes to **Settings → Provider**, not Runtime → Providers. Dumping Chat setup into the proxy catalog would violate A5 (`LlmRuntime` ≠ HTTP proxy listener) and would imply Chat requires the listener.

Settings → Server remains the saved bind/lifecycle form for the built-in proxy (tests and `saveSettings` already own it). Runtime → HTTP proxy is the operational listener surface. Copy must point between them; A9 does not delete either control.

## Runtime vs Settings (A9.6 / A9.7)

User-visible distinction (A5, unchanged architecture):

- **Provider configuration powers Chat** via Settings → Provider (`agent_secret_*`, Agent Engine). Chat does **not** require starting the HTTP listener.
- **HTTP proxy exposure is optional** (Runtime → HTTP proxy). Same process the Settings → Server form configures.
- **OAuth / connection status** is Runtime → Connections (`/oauth`).
- **Proxy upstream catalog** is Runtime → Providers (`/proxy-providers`).

One conceptual Runtime area; multiple routes.

Settings groups after A9:

| Group | Sections | Why |
|-------|----------|-----|
| Setup | Overview, Provider, Voice | Chat-ready prefs |
| Local tools | Agents, Extensions, Sessions, Server | Was labeled “Runtime”; rename to avoid colliding with product Runtime |
| Project | Tools, Paths | Project defaults |
| App | Appearance, Data, About | True application prefs |

Do not move Chat keys onto the proxy catalog page. Do not import parked OAuth/proxy WIP.

## Primary workbench flow

```text
Launch OpenMesh
  → Open / select project          (sidebar Projects)
  → Chat                           (/agent-chat)
  → continue session or start work
  → Plan / Act / Verify            (A7 slash grammar unchanged)
  → review patch / evidence        (host-authorized Apply/Reject; A6 /verify)
  → Pending & LAN when relevant    (A6 WorkSignals, unchanged)
```

Missing Chat provider:

```text
Chat banner
  → Settings → Provider
  → return to Chat
```

Infrastructure is reachable; it does not intercept this flow unless Chat keys are missing.
