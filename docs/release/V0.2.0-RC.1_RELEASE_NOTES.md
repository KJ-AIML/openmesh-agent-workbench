# OpenMesh v0.2.0-rc.1 Release Notes

**Release Candidate 1**  
**Tag / Baseline:** `v0.2.0-rc.1`  
**Date:** 2026-09-09  

OpenMesh v0.2 consolidates the product around a single clear identity: **OpenMesh is a local-first Agent Workbench for developers.**

This release candidate replaces the fragmented experiments of the 0.1.x era with a cohesive, project-centric architecture.

---

## 1. Unified Agent Workbench

- **Agent Chat as Primary Work Surface:** Chat is the center of the workbench, supporting Ask, Plan, Act, and Delegate modes.
- **Multi-Session Interoperability:** External agent scanner indexes sessions from Codex, Claude Code, OpenCode, Cursor, Gemini, and Grok with *Continue in Chat* and external CLI resumption.
- **Embedded PTY & Confined Tool Execution:** Integrated tabbed pseudo-terminal sidebar (`portable-pty`) bound to project working directories with output capture and session run history.
- **Human-Gated Patch Authority:** Agent patch proposals generate interactive diff inspections requiring explicit user approval before filesystem application, verification, or rollback.

---

## 2. Secure Agent Execution

- **Centralized Turn Authorization:** `authorize_agent_turn` enforces origin validation, capability checks, and role-based tool allowlists before any LLM or system call.
- **Remote Origin Confinement:** Remote clients (e.g. LAN peers) are strictly forbidden from proposing patches or mutating project files.
- **Desktop Security Hardening:** Default listener binding to loopback (`127.0.0.1`), strict webview Content Security Policy (CSP), removal of `plugin-fs`, and path canonicalization with traversal rejection.

---

## 3. Unified Provider Runtime

- **Direct OpenAI-Compatible Execution:** Agent Chat executes directly against OpenAI-compatible APIs with credential storage in secure OS storage (mode `0600`).
- **Optional HTTP Proxy Gateway:** Built-in local HTTP proxy (`localhost:8317`) for external client integration, complete with port conflict detection and health checks (`/v1/health`).
- **AXGA Boundary Clarification:** AXGA is retained strictly as an adapter for the tool-free Work Proxy draft and evidence boundary (ADR-0002).

---

## 4. Work Provenance & Continuity

- **Boundary-Driven WorkSignals:** Chat actions (patch proposals, apply/reject outcomes, verifications, handoffs) emit `WorkSignal` events without polluting the immutable `WorkEvent` ledger.
- **Deterministic Provenance:** WorkSignals record producer references, project IDs, and deduplication hashes to prevent replay collisions.

---

## 5. Explicit Chat Commands

- **Strict Slash Command Parser:** Local commands (`/plan`, `/act`, `/delegate`, `/verify`, `/rollback`, `/clear`) are explicitly distinguished from model prompts.
- **Context Mentions:** `@docs`, `@notes`, and `@context` provide deterministic prompt grounding.

---

## 6. Typed Desktop IPC

- **Contract Integrity:** 80 typed commands, 54 legacy contained commands, 10 unused diagnostic commands, and 0 unknown invoked commands.
- **Static Contract Enforcement:** Continuous validation via `npm run check:ipc`.

---

## 7. Product UI Consolidation

- **Single-Source Navigation Registry:** `src/lib/navigation.ts` organizes all views into 4 cohesive groups: Workspace, Agents, Runtime, and Settings.
- **Decomposed Chat Surface:** Dedicated mode switcher, composer menus, token metrics, and embedded terminal dock.

---

## 8. Core Architecture Hardening

- **Domain Decomposition:** Monolithic `domain.rs` decomposed into focused submodules under `crates/openmesh-core/src/domain/` (`events`, `signals`, `corrections`, `projections`, `profile`, `context_pack`, `proxy_draft`).
- **Concurrency Protection:** Unique sequence counters eliminate parallel test collisions.

---

## 9. Known Limitations

- **Non-Streaming Agent Engine:** Turns return full assistant text and executed tool steps upon completion rather than token-by-token streaming.
- **Direct Chat Endpoint Compatibility:** Direct Chat requires OpenAI-compatible endpoints; Claude/Gemini formats must route through the built-in HTTP proxy.
- **LAN Collaboration Identity:** LAN pairing uses local bearer tokens rather than end-to-end cryptographic identity.
- **Unsigned Preview Builds:** Installers remain unsigned for local developer dogfooding (macOS Gatekeeper / Windows SmartScreen guidance provided).
