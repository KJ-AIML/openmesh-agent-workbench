# OpenMesh v0.2.0-rc.1 Release Candidate Test Matrix

This matrix documents the verification coverage across all ten core product lifecycle areas for **OpenMesh v0.2.0-rc.1** ("OpenMesh is a local-first Agent Workbench for developers").

---

## 1. Lifecycle Areas & Test Coverage

### Area 1: Project Lifecycle
* **Capabilities**: Project creation, directory validation, switching active projects, updating metadata (target branch, docs path, terminal cwd), project deletion with cascade cleanup, web browser folder picking fallback.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/project.rs`: validation rules, name and path constraints.
  - `src-tauri/src/domain/project.rs`: project persistence and validation.
* **Frontend Unit Coverage**:
  - `src/stores/projectStore.spec.ts`: active project management, project listing, and switching.
* **E2E Playwright Coverage**:
  - `e2e/project-lifecycle.spec.ts`: validates, creates, switches, edits, and deletes projects; covers browser prompt folder-picking fallback (`runtime: "web"`).
* **Manual / Smoke**:
  - Project switching reflected across Chat, Continuity, and Titlebar.

---

### Area 2: Agent Lifecycle
* **Capabilities**: Agent definition, system instructions, mode selection (`plan`, `act`, `delegate`), context pack assembly, turn authorization (`authorize_agent_turn`), turn execution via LlmRuntime, in-flight abort / stop turn.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/agent.rs`: agent entity validation, state transitions.
  - `crates/openmesh-core/src/engine/`: turn execution pipeline, context packing, and turn result handling.
* **Frontend Unit Coverage**:
  - `src/lib/agentChat/llmRouting.spec.ts`: direct provider routing, fallback logic, and message normalization.
  - `src/components/chat/AgentComposer.spec.ts`: mode picker (`plan`, `act`, `delegate`), slash command completion, and stop button dispatch.
* **E2E Playwright Coverage**:
  - `e2e/agent-chat.spec.ts`: mode switching, sending prompts, rendering direct provider replies, stopping in-flight browser turns.
* **Manual / Smoke**:
  - Prompt streaming / turn completion in desktop Tauri app against real OpenAI-compatible endpoint.

---

### Area 3: Patch Lifecycle
* **Capabilities**: Code patch proposal generation from agent turns, diff inspection, approval & application to filesystem, verification against tests, handoff, rollback, and patch rejection.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/patch.rs`: patch data structures, diff parsing, and verification checks.
  - `src-tauri/src/commands/`: patch apply and rollback handlers with directory path validation.
* **Frontend Unit Coverage**:
  - `src/components/chat/AgentPatchCard.spec.ts`: patch state transitions (`proposed` -> `approved` -> `applied` / `rejected`), disabled states, and rollback actions.
* **E2E Playwright Coverage**:
  - `e2e/agent-chat.spec.ts`: approves, verifies, hands off, and rolls back a patch; rejects proposed patch without applying.
* **Manual / Smoke**:
  - Validating git status diff in actual repository after patch application.

---

### Area 4: Provider Lifecycle
* **Capabilities**: Provider configuration (OpenAI, Anthropic, Gemini, Ollama, Local AI, Custom), model selection, API key storage / status redaction, validation, fallback handling, secret check (`agent_secret_status`).
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/provider.rs`: provider profiles, validation, endpoints, and credentials handling.
  - `crates/openmesh-core/src/llm/`: provider transport adapters and error classification.
* **Frontend Unit Coverage**:
  - `src/lib/agentChat/directProvider.spec.ts`: key configuration, endpoint resolution, payload formatting.
  - `src/pages/ProxyProvidersPage.spec.ts`: provider configuration form, custom models, and validation errors.
* **E2E Playwright Coverage**:
  - `e2e/provider-configuration.spec.ts`: provider configuration, editing endpoints, custom headers, and fallback state.
  - `e2e/agent-chat.spec.ts`: provider setup guidance and redacted provider failure notices.
* **Manual / Smoke**:
  - Verification that API keys are never rendered in plaintext in logs or session transcripts.

---

### Area 5: HTTP Proxy Runtime Lifecycle
* **Capabilities**: Built-in HTTP proxy daemon management (start, stop, port bind, status), OpenAI-compatible proxy gateway, protocol translation, `/v1/health` endpoint, error handling on port conflicts or missing upstreams.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/proxy_draft.rs`: proxy configuration, target routes, and draft validation.
  - `src-tauri/src/proxy/`: Axum server lifecycle, listener bind, health checking, and graceful shutdown.
* **Frontend Unit Coverage**:
  - `src/pages/ProxyRuntimePage.spec.ts`: runtime status display, port configuration, start/stop toggle, error banners.
* **E2E Playwright Coverage**:
  - `e2e/proxy-runtime.spec.ts`: starting default runtime, stopping runtime, port conflict handling, upstream failure reporting.
* **Manual / Smoke**:
  - `curl -s http://127.0.0.1:<port>/v1/health` returning valid JSON status while runtime is active.

### Area 6: Sessions & History Lifecycle
* **Capabilities**: Session creation, session list indexing, switching active sessions, chat transcript persistence, session forking from specific turns, run history recording, and restoring past conversation states.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/session.rs`: session entity, turn serialization, and transcript schemas.
  - `src-tauri/src/domain/session.rs`: session persistence on disk and atomic file writing.
* **Frontend Unit Coverage**:
  - `src/lib/agentChat/sessionPersistence.spec.ts`: session serialization, transcript parsing, and migration compatibility.
* **E2E Playwright Coverage**:
  - `e2e/agent-chat.spec.ts`: fork chat from message action, start new chat clearing active conversation.
  - `e2e/residual-coverage.spec.ts`: session management, transcript export, and session switching.
* **Manual / Smoke**:
  - Restarting the workbench desktop application and verifying that all historical sessions reload intact.

### Area 7: LAN & Network Lifecycle
* **Capabilities**: Peer discovery over local network, peer presence status, pairing requests, remote work signal propagation, connection status monitoring.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/lan.rs`: peer representation, handshake message validation, network payload schemas.
  - `src-tauri/src/domain/lan.rs`: network interfaces, discovery broadcasts, and socket listeners.
* **Frontend Unit Coverage**:
  - `src/stores/networkStore.spec.ts`: peer list state, connection indicator, and error notifications.
* **E2E Playwright Coverage**:
  - `e2e/secondary-coverage.spec.ts`: LAN status, peer listing, and discovery toggle.
* **Manual / Smoke**:

### Area 8: Security & Sandbox Lifecycle
* **Capabilities**: Workspace root boundary enforcement, path traversal rejection, command allowlist and blocklist checks (blocking destructive commands like `rm -rf /`), secret redaction in UI/logs, and Tauri IPC invoke authorization.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/security.rs`: path boundary validation, command safety classifier.
  - `src-tauri/src/ipc/authorization.rs`: command authorization checks before execution.
* **Frontend Unit Coverage**:
  - `src/lib/ipc/client.spec.ts`: typed command validation, unknown command rejection, and error normalization.
* **E2E Playwright Coverage**:
  - `e2e/agent-chat.spec.ts`: verifying secrets are redacted in provider error payloads.
  - `e2e/residual-coverage.spec.ts`: security path validation and blocked command execution.
* **Manual / Smoke**:
  - Attempting to pass out-of-boundary paths via IPC and ensuring strict rejection by Rust backend.

### Area 9: Continuity & WorkSignals Lifecycle
* **Capabilities**: Work signal creation (`WorkSignal`), signal observation across workspace events, deduplication, promotion policy to `WorkEvent`, continuity board display, and filter by project/type.
* **Rust Backend Coverage**:
  - `crates/openmesh-core/src/domain/continuity.rs`: signal schemas, work event schemas, promotion policies, deduplication hashing.
  - `crates/openmesh-core/src/domain/context_pack.rs`: context packing with deterministic signal ordering and concurrency protections.
* **Frontend Unit Coverage**:
  - `src/components/continuity/ContinuityBoard.spec.ts`: signal display, event filtering, and promotion triggers.
* **E2E Playwright Coverage**:
  - `e2e/settings-continuity.spec.ts`: viewing continuity signals, filtering work events, empty state handling.
* **Manual / Smoke**:
  - Triggering concurrent actions in the workspace and verifying that context packs do not race or duplicate signals.
